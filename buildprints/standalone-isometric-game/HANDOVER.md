# Game handover

Write the actual handover in the host's `.buildprint/handover.md`, linking existing upstream acceptance records rather than maintaining a second verdict table. Do not claim completion beyond the evidence.

## Built
State the host path, framework commit and vendored archive hash, actual build identity, original assets/maps, implemented requirement IDs, full included content and remaining content. Distinguish calibration from the final game. Include authorized run/build commands from the generated package.

## Verified
Separate functionally verified, visually accepted, motion accepted and measured performance. Link candidate, receipts, comparison rounds, clips and reviewed viewports/devices. Name reviewer independence honestly and record the owner's acceptance decision if one was requested. Emulation is not a physical-device claim.

## Blocked
Give exact authorization, capability, budget, asset/license, API or capture blocker, last fresh evidence, attempted strategy change, and decision needed. Preserve prior approvals and provide a concrete continuation owner/path, not an indefinite promise.

## Not proven
List every untested device, action, mode, stale criterion and missing capture/review. Report total known/uncertain spending, provenance limitations and explicit fallback quality limits. Package loading, type checking and screenshots alone are not complete-game proof. No push/deploy/hosting claim without a separately authorized and proven release.

## Next
Name the next eligible check from upstream production status and current loop, unresolved defects and remaining agreed scope. Preserve immutable snapshots/receipts and reference the contract amendment history. For stopped work, offer the actual next loop or blocker decision; do not solicit redundant permission to continue already-authorized work.
