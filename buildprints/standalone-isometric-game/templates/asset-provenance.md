# Asset provenance record — host-owned data

Use one record per asset family/output; link actual technical manifests rather than duplicate their frame/collider values.

- Contract requirement IDs and family role:
- Source creator/provider/model, public source or job identity (no signed/private URLs):
- License text/version, attribution, modification/redistribution/commercial permission:
- Approved upload/reference roles and source hashes; exact secret-free prompt/request:
- Original local files and SHA-256; rejected candidates retained separately:
- Edits/removal/crop/packing tools, versions and processed file hashes:
- Runtime image path, actual manifest/clip IDs and exported host binding:
- Measured alpha/crops/scale/contact results and actual in-game review links:
- Generation budget/job record if applicable; known and uncertain cost:
- Technique disclosure (e.g. generated materials with deterministic assembly):
- Explicit fallback quality limitation and unresolved requirements:

A provider URL is not a durable production asset. An atlas entry does not prove the game loads it, and a license label without its source is not rights evidence.
