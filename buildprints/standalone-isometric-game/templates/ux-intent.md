# UX intent outline — embed in PROJECT_CONTRACT.md

Do not create a competing UI brief. For each agreed screen/state, record:

| Intent | Contract content |
| --- | --- |
| Purpose | What the player accomplishes in this state. |
| Hierarchy | World/actor/objective first; essential resources/feedback next; secondary settings last, adjusted to this game. |
| Next action | Visible action, eligibility, success/failure feedback and recovery. |
| Touch | Reach, target spacing, safe areas, movement/action/camera separation, multi-pointer handling and cancellation. |
| Presentation | Portrait/landscape world framing, UI footprint, text scale and modal behavior. |
| Desktop | Keyboard/focus, pointer and camera adaptation without hover-only essentials. |
| Evidence | Real input journey and protected viewport/state that will prove the intent when acceptance is authorized. |

Cover start/loading/error, play, pause/settings, contextual actions, result/restart and every promised menu/inventory/save state. List not-applicable states rather than inventing features. Accessibility and reduced-motion/audio choices must have real effects. A beautiful target image is not interaction evidence.
