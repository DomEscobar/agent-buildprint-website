# Execution flow: whole game, one contract

Run goal → bare agentic loop (think → act → observe until done or genuinely blocked) → optional independent fan-out → contract review. Read the active loop only plus its linked references, not every specialist recipe at once. Do not create extra paperwork; the contract owns requirements, framework receipts own acceptance state, and versioned CLI state owns current loop routing and attestation links; compact progress notes summarize it. Edits alone are not proof: do not fake live success.

The six packet loops organize ownership; they do not replace the framework's six production stages. Loop 01 establishes preflight/layout and protected coverage; loop 02 calibrates the riskiest playable assembly; loop 03 expands complete static content; loop 04 completes mechanics/motion; loop 05 runs authorized whole-game acceptance; loop 06 hands over the actual result. Art and gameplay may proceed in parallel after relevant approvals, within eligible production checks. Graybox is optional for focused uncertainty, never compulsory art gating. Approved calibration is reused, not re-approved every round.

Use `production status` for next eligible checks and unchanged receipt reuse. A failed prerequisite blocks dependent expansion, not all independent authorized work. Fan out only disjoint files/check inputs, with one integration owner and one spend owner. Never fabricate separate reviewers using alternate builder labels. Report progress at stage completion or a real blocker; a running child is not completion and the owner retains follow-through.

For environment/tool problems return to `01-setup.md`; requirement or consequential art changes return to `00-goal.md` for only the unresolved decision; UX intent conflicts return to `02-identity.md`. Preserve approved contract answers and exact scope. After two failed attempts on a production check, use the upstream changed-strategy requirement; a continuing material blocker escalates with evidence, never automatic quality reduction.

If future tests, captures or reviews are not authorized, do not run them. Record evidence-dependent work as unverified and do not declare a quality gate passed. If implementation may continue, keep dependency limitations explicit. Read `review.md` before final completion and `HANDOVER.md` before stopping. No push/deploy unless separately requested.

## Explicit CLI transitions
`runtime.json` preserves the six loop IDs and dependencies. Read `agb loop next`; record actual contract/setup/UX/asset/acceptance approvals, then `loop begin`. Bind current build/assets/runtime and original targets with `evidence bind`, record actual evidence with `evidence record`, select each required dimension using `loop accept`, and only then `loop advance`. This schedules no agent or command. `loop return` routes alignment/setup/identity blockers; `loop defect` invalidates affected/dependent completion and requires fixes plus fresh evidence before resolution. Stale predecessors need explicit fresh re-attestation. Snapshot loop-index is immutable; do not edit it or legacy state.json to force progress. See `references/cli-integration.md` for receipts, command syntax and recorded-claim limitations.
