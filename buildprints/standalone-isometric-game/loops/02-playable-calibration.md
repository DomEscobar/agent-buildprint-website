# Calibrate original art and the core interaction

## How to implement this loop
Read the host `AGENTS.md`, `.buildprint/next-agent.md`, approved `PROJECT_CONTRACT.md`, packet `02-identity.md` and `loops/loop-flow.md`. Resolve packet paths relative to immutable snapshots after bootstrap; host data paths are relative to the game root. Load only relevant pinned framework skills under the available tool policy. Run only authorized work, with concise progress updates and durable upstream receipts.

1. Select specialists from the pinned catalog by technique: art integration for contacts; tileset composition for material boundaries; multi-tile assembly for support/depth; directional sprites and animated environments for required motion. Generation is conditional and governed by the preferred-stack capability/budget policy.
2. Begin eligible assembly checks before work/evidence. Establish intended actor-relative scales and rigid contacts before measuring candidates. Use original host art and measured decoded crops; retain source, rejected frames and approved identity crops with provenance.
3. Bind scene and packed-art data to actual runtime definitions. Use named textures/clips with stable source scale/root, visible facing and intended action coverage. Inspect upstream packed previews at shared scale; group subsets are clearly calibration-only and do not reduce final protected art groups.
4. Build the host-owned playable patch with public APIs. Inspect ground-only while retaining roots/wear/bank contacts, then dressed assembly. Walk the actor in front/behind objects and through actual approach/landing poses. Verify both support and visible contact: a shadow cannot repair missing ground and a nonblocking sprite can still cover feet.
5. Exercise a real player verb, feedback, objective or intermediate rule and recovery using intended touch/desktop input. Apply the mobile-first intent before UI coding; reserve controls without shrinking the world. Art and mechanic work can proceed in parallel within eligible checks; graybox is not mandatory.
6. Under requested acceptance, observe motion playback/wrap/pause and actual gameplay, collect fresh views and obtain the scoped upstream review. Correct blockers before expansion. Reuse valid calibration rather than ask the user to approve unchanged decisions again.

## Building objective
Produce the smallest representative playable assembly that can disprove the proposed production approach: the game's actor, a grounded object or risky structure, material transitions, appropriate motion and one real observable rule. This milestone establishes shared projection, physical proportions, animation identity and mobile controls at playing zoom. It must expose front/behind occlusion, contact drift and interaction arrival problems rather than hide them in a contact sheet. A successful patch unlocks expansion of the full agreed game; it does not become a substitute deliverable or justify excluding difficult action directions, routes, interiors or world regions.

## DO NOT
Use placeholders, functionless buttons or mocked/sample data as final product or live proof. Do not copy demo/example assets/maps, edit framework internals, invent APIs or commands, spend without approval, weaken protected criteria, fake independent review, or reinterpret calibration as the full deliverable. No tests/benchmarks/browser QA/independent review during packet AUTHORING; this loop describes future authorized game work.

## Minimum proof before moving on
Current packed-art/geometry results plus actual ground-only/dressed captures, approach/occlusion views, motion playback and real action/recovery evidence. Record which planned art groups and mechanics remain unbuilt; only observed calibration passes, not the full game's acceptance. Cost/provenance and missing essential capabilities remain visible.

## Handoff note
Record the actual implemented scope, observed evidence, exact candidate/inputs, open defects and capability/authorization blockers. Link upstream production status/receipts instead of copying their verdicts. Keep current loop/next eligible work in local progress; the immutable packet index is not an auto-advancing scheduler. Preserve approvals, full scope and delegated-work ownership.
