# One upstream visual loop, no substitute ceremony

Read the pinned `isometric-visual-loop/SKILL.md` plus its `references/acceptance.md`, `production-flow.md`, `visual-comparison.md` and `production-brief.md` through `references/framework.md`. These are the operational authority for the v3 production plan, receipts, comparison board and acceptance tool. Reuse them; do not create a second ledger or custom validator.

## Translation before production
Use the complete upstream `acceptance-plan.example.json` version 3, not disconnected version 1/2 snippets. Derive a host-owned `.game-quality/acceptance-plan.json` with `root` resolving to the game root, `contract: PROJECT_CONTRACT.md`, full requirement IDs and protected views. Read `templates/acceptance-plan-routing.md`. Include every promised visual, motion, gameplay and performance outcome; the agent translates prose and checks coverage. No user questionnaire about internal hashes or check schemas.

Select `reviewMode: independent` when a genuinely separate authorized reviewer can inspect evidence. If unavailable, declare `self` before freezing and disclose it; do not invent a reviewer identity or count repeated builder prompts as independence. If the contract requires independence, unavailable review is a blocker. Missing capture/vision or denied acceptance execution means unverified, not pass.

Preserve the original reference, its style/layout/both role, target hash, camera/state and viewport intent. Text criteria alone cannot fabricate image-comparison acceptance. A new concept must be attainable at gameplay scale and cannot replace a supplied target. A retrospective baseline must be labeled retrospective.

## Upstream production sequence
Use the tool's `freeze`, then `production begin` BEFORE work/evidence for each eligible check, `production draft` for hash-bound submissions, actual review, `production finish` for immutable receipts, and `production status` for eligibility. Exact argument forms are in the pinned guide; use absolute installed script paths from the game root, never guessed CLI flags. Outputs live outside all `inputRoots`.

- **preflight:** selected asset loads in dev AND production, real projection/pixel scale, actual provider capability only when needed.
- **layout:** one semantic authority drives regions, routes, supports, entrances and host placements. Public `project` or a host export supplies projection. The flat helper cannot certify slopes/multi-floor routes; retain those requirements and use real host evidence.
- **assembly:** riskiest playable actor/object/contact/motion composition, measured rigid binding and actual controls. Review ground-only with contact beds retained, dressed patch, and arrival poses. This is calibration, not the agreed full game.
- **static:** complete connected world and all instances, not just the camera's favorite corner. Ground composition, material transitions, dressed scene, regions and touch view coverage.
- **motion:** all promised actor facings/actions and environmental cycles, joined parts, loop wrap, pause, input, interactions and performance evidence. Still screenshots cannot substitute.
- **final:** full current candidate and whole-image review; prerequisite receipts must be valid. Reuse unchanged dependency receipts only; final inputs cover every input root.

Inspect actual packed art with upstream `inspect` after art changes and open its shared-scale preview. `--groups` is calibration-only; final acceptance covers all protected groups. Export bindings from the actual host; a handwritten passing sidecar cannot prove loaded content.

## Capture → critic → repair → fresh capture
1. Bind candidates to exact code (including dirty/untracked inputs), installed runtime, lock/config, actual loaded scene definitions, maps, asset manifests, atlas images and reference/contract hashes. A git commit alone cannot identify a dirty running build. Record build command/output identity, actual served route and source-to-bundle correspondence using `templates/capture-receipt.md` as supporting evidence, not a competing acceptance ledger.
2. Capture the running host at the protected viewports, camera/zoom, floor, state and normal input paths. Self-inspect loading/crop errors. No mockups, image edits, stale screenshots, demo hosts, proof-only renderers, hidden UI defects, forced reward state or preview boards posing as game proof.
3. Use upstream `snapshot` and `compare` with actual captures and later `--previous` review. For version 3, use the documented production-receipts option for candidate snapshot and final acceptance. Give the fresh reviewer the contract, original targets, packed preview, current/previous pixels and open findings, without builder rationale or a preferred score. Reviewer must actually inspect images/playback; hashes cannot judge beauty or authenticate independence.
4. Obtain pass/fail/unverified per protected requirement/view, localized visual differences and concrete repair. Review composition/readability, material transitions, scale, physical support, contacts, occlusion and motion separately. Check actor feet at near/middle/far crossing, both landings and interaction endpoints from real approaches, not only route success.
5. Fix actual host/assets; preserve prior failures. New source snapshot and fresh captures follow every repair. Reassess each prior finding as resolved/open/regressed with evidence; retain the complete defect list while prioritizing at most three root causes per round. No inherited PASS after affected inputs change.
6. After two failed attempts on a check, use upstream's required changed-strategy record and discriminating observation. If the changed strategy still cannot resolve the same material blocker, escalate the exact capability, asset, geometry, budget or authorization decision with last evidence; do not loop indefinitely. This bounds retries without capping world scope or declaring unfinished work complete. Continue independent authorized work where useful.
7. Run upstream `accept` on the current complete candidate/review/production receipts when authorized. A structural tool pass is not a visual or gameplay verdict. Report every stale, failed, missing or unverified requirement and do not weaken thresholds, alter targets, substitute placeholders or remove scope to get green.

## Beyond still images
Observe complete cycles and wrap, stable feet/rigid contacts, direction mapping, joined motion, pause/resume and context timing. The acceptance tool requires supported motion media per motion view; a timed still sequence alone does not satisfy that media gate. Gameplay proof uses normal start → action → objective/failure/undo → restart and promised saves/modes, with real input and authoritative state outcomes. Cover touch multi-pointer/cancellation and camera-picking after transforms where supported. Performance is measured against the agreed budget with median/p95 intervals, viewport/browser/renderer and blank baseline; emulated software rendering is not native GPU evidence. No synthetic tests, frame IDs, image counts, HTTP 200 or a passed build substitute for these observations.

The local 2d-game-quality-loop informed observable targets, claim separation and anti-cheating. Its separate contract.md/art-direction.md/manual acceptance ledger and automatic deployment step are intentionally NOT adopted. All human requirements stay in PROJECT_CONTRACT.md; upstream production receipts carry live status; deployment needs a separate explicit request.

## Versioned CLI linkage (routing, not another critic)
The opt-in `runtime.json` references this same upstream plan and production receipts. Use `agb evidence bind/record`, then explicit `agb loop accept/advance` with current revision receipts; retain the original upstream evidence paths/hashes. CLI kinds require running captures plus supported motion media, interaction and review observations, with whole-plan requirement/view coverage for final loops. It checks byte freshness and required recorded claims only, never pixel quality or reviewer independence. `loop defect` reopens affected work; close it only with actual fixes and fresh same-dimension evidence. New bindings conservatively stale previous loop attestations, which must be refreshed in dependency order. This does not replace the upstream granular production eligibility or justify weakening criteria. See `references/cli-integration.md`.
